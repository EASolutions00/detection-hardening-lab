Proposed Title
Automated Detection of Severity Inversion in the Wazuh Default Ruleset Using Parent-Child Dependency-Graph Analysis and Topological Consistency ScoringArea of Investigation
          The study falls under the field of cybersecurity, specifically within the sub-disciplines of security operations, detection engineering, and the quality assurance of detection content. Security operations refers to the continuous practice of monitoring, detecting, investigating, and responding to malicious activity across an organization's computing infrastructure. This function is typically institutionalized in a Security Operations Center (SOC), where security analysts work from a queue of alerts generated by automated monitoring platforms rather than by observing raw system activity directly.
          The technological foundation of this practice is the Security Information and Event Management (SIEM) platform, which collects log data from distributed sources, normalizes that data into a common structure, and evaluates it against a library of detection rules. Wazuh, an open-source SIEM and Extended Detection and Response (XDR) platform derived from the earlier OSSEC project, is widely deployed by organizations that require this capability without the licensing cost of commercial alternatives, including small and medium enterprises, academic institutions, and public sector agencies in developing economies. Its detection logic is expressed as a set of rules defined in Extensible Markup Language (XML), each identified by a unique numeric identifier and each assigned a severity level on a fixed ordinal scale.
          Severity level is the mechanism by which a monitoring platform communicates urgency. It determines whether an alert is written silently to storage, surfaced in an analyst queue, escalated to a supervisor, or dispatched as an out-of-hours notification. Alert routing, notification thresholds, retention policy, and response service level agreements are commonly configured as functions of this single value. Because analysts in most operational environments receive far more alerts than can be examined individually, a condition documented in the literature as alert fatigue, the accuracy of severity assignment governs which events actually receive human attention. An event graded below its true urgency is, in practical terms, an event that will not be investigated.
          A defining architectural characteristic of rule-based detection platforms is that rules are not independent of one another. Rule languages permit a rule to declare a dependency on another rule, so that the dependent rule is evaluated only when its antecedent has already matched. This construct allows engineers to compose general-purpose parent rules that classify a broad category of activity with specific child rules that refine the classification. The consequence is that a rule set is not a flat list but a directed graph, in which rules are vertices and dependency declarations are edges. Properties of such a structure are emergent rather than local: a characteristic of any individual rule may be determined by rules several dependency hops away from it, and cannot be established by examining the rule in isolation.
          The authorship and maintenance of detection content has matured into a discipline known as detection engineering, which treats detection logic as a software artifact subject to a lifecycle of authoring, version control, review, testing, deployment, and retirement. This practice is frequently described as detection-as-code, reflecting the adoption of software engineering methods such as source control and continuous integration for rule content. A characteristic property of large public rule sets is distributed and incremental authorship: content accumulates over many years through contributions from vendor engineers and community members, each working on a narrow portion of the whole, with no single contributor holding a complete view of the dependency structure.
          The verification of properties over graph-structured artifacts is an established concern of computer science. Graph theory provides the formal apparatus of directed graphs, topological ordering, strongly connected components, and reachability analysis. The field of static analysis, developed principally for the examination of program source code without executing it, contributes the technique of constraint propagation, in which a property asserted at one point in a structure is propagated along its edges to infer bounds on that property elsewhere, with violations of the inferred bounds reported as defects. Dataflow analysis and type checking are canonical applications of this approach. The extension of static analysis methods from program code to declarative configuration and rule artifacts, together with the automated linting of such artifacts for quality defects, forms the broader methodological context in which this study is situated.

          In current practice, the severity level of a detection rule is assigned manually by its author at the time of writing. A rule engineer examines the activity to be detected, forms a judgment about its urgency, and records a numeric level in the rule definition. Where the new rule declares a dependency on an existing parent rule, the author is expected to consider whether the assigned level is coherent with the level of that parent, but this consideration is informal and is not recorded anywhere in the artifact. Contributions to the public rule set are submitted through a source control platform and reviewed by maintainers, whose review is a manual reading of the submitted change.
          The automated validation available to this process addresses other concerns entirely. Structural validation confirms that rule files conform to the expected schema and that the platform can load them without error. A duplicate-identifier check confirms that no two rules claim the same numeric identifier. A log testing utility permits an engineer to submit a single sample log line and observe which rule matches it, which verifies matching behavior for that one input but says nothing about the coherence of the rule set as a whole. None of these checks examines severity level at all.
          Consequently, an engineer wishing to verify that severity levels are coherent across the rule set has no alternative to manual inspection. This requires opening the rule definition files, locating a rule of interest, reading its declared dependency, locating the referenced parent rule in what may be a different file, comparing the two levels, and then repeating the exercise along the full ancestor chain. Performed across a rule set containing several thousand rules and a comparable number of dependency edges, this is not an activity that any engineer undertakes in practice. The result is that severity inconsistencies are discovered empirically and incidentally, typically when an analyst observes that an alert which should have been escalated arrived at a level too low to trigger notification, or when a rule intended as a broad classifier generates a volume of high-severity alerts disproportionate to its purpose. This gap in the current process gives rise to the following problems.

Statement of the Problems

1. Severity levels in the rule set are assigned manually and independently for each rule, and no automated mechanism verifies that the level assigned to a rule is coherent with the levels of the rules on which it depends, so inconsistent assignments enter the rule set undetected.
2. Because rule dependencies form a multi-level directed graph rather than a flat list, a severity inconsistency may originate several dependency hops away from the rule at which it becomes observable, and an inspection limited to a rule and its immediate parent is therefore structurally incapable of detecting this class of defect.
3. Manual auditing of severity coherence is not feasible at the scale of the rule set, which contains several thousand rules distributed across many files, so the audit is not performed in operational practice and the true extent of the defect population is unknown.
4. The validation tooling presently available for the rule set is confined to schema conformance, duplicate identifier detection, single-input match testing, and structural properties such as cycles and orphaned rules, leaving severity coherence entirely outside the scope of existing quality assurance.
5. There exists no formal criterion that distinguishes a deliberate and legitimate severity escalation, such as a general classifying rule of minimal severity giving rise to a specific child rule of high severity, from a genuine severity defect, so observed inconsistencies cannot be classified, counted, ranked, or reported objectively.

Objectives of the Study

General Objective. The study aims to design, develop, and evaluate a system that automatically detects severity inversion in the Wazuh default rule set by constructing the parent-child dependency graph of the rule set, propagating expected severity bounds across that graph, and assigning a topological consistency score to each rule, so that severity defects can be identified, classified, and ranked without manual inspection.

Specific Objectives.
1. To design and implement a formal severity-consistency predicate together with a severity-bound propagation algorithm that infers, for each rule, the range of severity levels consistent with its position in the dependency graph, thereby providing the automated verification of level assignment that the rule set presently lacks. (addresses Problem 1)
2. To construct the directed parent-child dependency graph of the rule set from its declared dependency relationships, with topological ordering and explicit handling of cycles and orphaned vertices, so that inconsistencies originating beyond a rule's immediate parent are made detectable through multi-hop analysis. (addresses Problem 2)
3. To automate the analysis across the complete rule set so that severity auditing scales to several thousand rules and dependency edges, and to measure the runtime, throughput, and analyzable coverage of the resulting implementation against a naive flat-scan baseline that compares each rule only to its immediate parent. (addresses Problem 3)
4. To develop a topological consistency scoring component that assigns a severity-inversion score to each rule and produces a ranked report of affected rules with their dependency subgraphs, extending the existing structural validation of the rule set to cover severity as a measurable quality dimension. (addresses Problem 4)
5. To formulate a taxonomy that distinguishes legitimate severity escalation from genuine severity inversion defects, and to evaluate the classification accuracy of the proposed system using precision, recall, and F1 score against a manually labeled subset and a seeded-defect benchmark in which known inversions are injected and their recovery measured. (addresses Problem 5)Project Context          The proposed system is a static analysis tool for detection rule content. It operates entirely offline on the rule definition files of the Wazuh rule set, requiring no live monitoring platform, no log ingestion, and no network access during analysis. The system reads the rule set, reconstructs the dependency relationships declared among its rules, and analyzes the resulting graph to determine whether the severity level assigned to each rule is coherent with the levels assigned to the rules connected to it.
          The central contribution is algorithmic rather than functional. The system does not merely compare each rule against its immediate parent, which is the comparison an engineer would perform by hand and which serves as the experimental baseline for this study. It instead computes a topological ordering of the dependency graph, propagates inferred severity bounds forward and backward along ancestor and descendant chains, and evaluates a formal consistency predicate at each vertex. Rules that violate the predicate are then classified against a defined taxonomy that separates deliberate escalation from genuine defect, assigned a numeric severity-inversion score, and presented in ranked order together with the portion of the dependency graph that produced the finding.
Features and Capabilities

* Automated parsing of the complete Wazuh rule set, including vendor-maintained rule files and locally authored custom rules
* Extraction of rule identifiers, severity levels, dependency declarations, rule groups, and override attributes into a normalized internal representation
* Construction of a directed parent-child dependency graph from the declared dependency relationships among rules
* Topological ordering of the dependency graph with detection of cycles, orphaned vertices, root rules, and leaf rules
* Multi-hop propagation of inferred severity bounds along ancestor and descendant chains
* Evaluation of a formal severity-consistency predicate at every analyzable rule
* Taxonomy-based classification distinguishing legitimate severity escalation from genuine inversion defects
* Computation of a severity-inversion score for each affected rule and generation of a ranked findings report
* Visualization of the dependency subgraph responsible for each finding, supporting analyst verification
* A naive flat-scan baseline mode that compares each rule only to its immediate parent, for experimental comparison
* A seeded-defect injection facility that introduces known inversions into the rule set for ground-truth evaluation
* Performance instrumentation reporting runtime, throughput, and the proportion of the rule set successfully analyzed
* Export of findings and graph data in machine-readable formats suitable for integration into a continuous integration pipeline

System Modules

The features above are organized into five modules.

* Module 1 - Rule Set Parsing and Normalization Module. This module ingests the rule set and converts it into the internal representation used by the remainder of the system. It traverses the rule file directory, parses each Extensible Markup Language file, and extracts for every rule its numeric identifier, severity level, dependency declarations, group memberships, description, and any override attributes. It tolerates malformed or non-conforming files without terminating the analysis, recording them instead as unparsed, and it reports the proportion of the rule set successfully normalized so that analyzable coverage can be stated as an explicit metric rather than assumed.
* Module 2 - Dependency Graph Construction Module. This module builds the directed graph on which the analysis operates. Each normalized rule becomes a vertex and each dependency declaration becomes a directed edge from antecedent to dependent. The module computes a topological ordering of the graph, identifies strongly connected components in order to detect dependency cycles, and classifies vertices as root, intermediate, leaf, or orphaned. Because a strict topological ordering does not exist in the presence of cycles, the module implements an explicit cycle-handling strategy that condenses each cycle to a single component so that ordering and subsequent propagation remain well defined.
* Module 3 - Severity Propagation and Consistency Analysis Module. This module contains the core algorithm of the study. Working in topological order, it propagates inferred severity bounds forward from antecedent rules to their dependents and backward from dependents to their antecedents, accumulating at each vertex the range of severity levels consistent with its position in the graph. It then evaluates the formal severity-consistency predicate at each vertex, comparing the declared level against the inferred bounds, and records every violation together with the dependency path that produced it. The module also implements the naive flat-scan baseline against which the proposed multi-hop approach is experimentally compared.
* Module 4 - Taxonomy Classification and Scoring Module. This module converts predicate violations into interpretable findings. It classifies each violation against a defined taxonomy separating legitimate escalation, in which a low-severity classifying parent deliberately gives rise to a high-severity specific child, from genuine defect categories such as unreachable high-severity descendants and silent de-escalation along a dependency chain. It computes a severity-inversion score for each affected rule, weighted by the magnitude of the level discrepancy, the depth and length of the affected dependency chain, and the number of descendant rules implicated, and it ranks all findings by that score.
* Module 5 - Evaluation, Reporting, and Visualization Module. This module presents results and supports the experimental evaluation of the study. It renders the ranked findings report and the dependency subgraph associated with each finding, and exports both findings and graph data in machine-readable formats. For evaluation it provides the seeded-defect injection facility, which introduces known severity inversions into a copy of the rule set so that recovery can be measured, and it computes precision, recall, and F1 score for both the proposed algorithm and the flat-scan baseline, together with runtime, throughput, and analyzable coverage.

Activity Diagram of the Proposed System

          The activity diagram below uses four partitions representing the Security Detection Engineer, the proposed system, the Wazuh rule set repository, and the Rule Maintainer. The flow proceeds from the selection of a rule set source through parsing, graph construction, cycle and ordering analysis, severity bound propagation, and consistency evaluation, terminating either in a recorded finding that the rule set is severity-consistent or in a ranked report of scored inversions. Findings confirmed as genuine defects proceed to correction by the Rule Maintainer and the analysis is repeated against the updated rule set, while findings judged to be legitimate escalations are annotated so that the taxonomy can be refined.
Importance of the Study

          To society. The severity level attached to a security alert determines whether that alert reaches a human being. Organizations that safeguard personal, financial, and medical information, including banks, government agencies, hospitals, and utilities, depend on this grading to direct limited analyst attention toward the events that matter. A detection rule that fires correctly but at an understated severity provides the appearance of coverage without its substance, since the resulting alert is recorded but never escalated. By making this class of defect detectable, the study contributes to the reliability of the alerting on which the protection of ordinary citizens' data ultimately rests. The benefit accrues particularly to organizations that rely on open-source monitoring because commercial platforms are beyond their means, a category that includes many small and medium enterprises, academic institutions, and public sector agencies in the Philippines.
          To the computer science and information technology security industry. The study delivers an automated quality assurance check for a class of defect that no existing tool addresses. Present validation tooling for the rule set examines syntax, duplicate identifiers, and structural anomalies such as cycles and orphaned rules, but no available tool evaluates severity coherence. Because the analysis is static and offline, it can be incorporated directly into the continuous integration pipeline through which rule contributions are reviewed, allowing defects to be intercepted before they are merged rather than discovered in production. The method is moreover not specific to one platform: any detection language in which rules may declare dependencies on other rules produces the same graph structure, so the approach is transferable to other rule ecosystems.
          To computer science as a discipline. The study applies the established methods of graph theory and static analysis to an artifact class that has received little formal treatment. It formalizes severity coherence, currently an informal expectation held by experienced engineers, as a verifiable property expressed through a consistency predicate over a directed graph, and it demonstrates constraint propagation as a means of inferring that property across dependency chains. It additionally produces a labeled benchmark of severity defects in a real, publicly available rule set, together with a seeded-defect harness, both of which supply the reproducible evaluation material that work on detection content quality has generally lacked.
          To security operations practitioners. For detection engineers and rule maintainers, the study converts an audit that is currently impossible to perform by hand into one that executes automatically over the entire rule set. It supplies not merely a list of differences but a ranked and classified set of findings, each accompanied by the dependency path that produced it, allowing remediation effort to be directed at the defects of greatest consequence. For analysts, the downstream effect is an alert queue in which severity more faithfully reflects urgency, which is a direct contribution to the mitigation of alert fatigue.
          To future researchers. The dependency graph representation, the consistency predicate, the defect taxonomy, and the labeled benchmark together provide a foundation on which subsequent work can build, including extension of the method to other rule languages, incorporation of additional quality dimensions beyond severity, and investigation of automated repair that proposes corrected severity levels rather than reporting violations alone.Target Users

STATIC QUALITY ASSESSMENT OF SIGMA DETECTION RULES: FRAMEWORK AND EMPIRICAL EVALUATION
Tyagi, Nishant (2026)

SSRN Working Paper, abstract ID 6823718, 2025; tool name "sigmalint"; evaluated on the SigmaHQ corpus (3,132 rules at commit 994da16). This is a preprint; formal peer-review status is unverified.

https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6823718

          This study addresses the problem that Sigma detection-rule quality (correctness, maintainability, operational usefulness, and freedom from false-positive patterns) is assessed primarily by manual review, which does not scale to large curated corpora. The author proposes a multi-dimensional framework for static detection-rule quality assessment, implemented in an open-source tool called sigmalint, and evaluates it against the full public SigmaHQ corpus of 3,132 rules at a pinned commit. The framework separates validity (a binary spec-conformance gate) from quality, the latter being a weighted score across six dimensions: ATT&CK alignment, taxonomy correctness, false-positive risk, metadata completeness, redundancy, and style. Scoring is described as size-invariant across dimensions with different rule counts and deterministic given pinned reference data. The work is explicitly a static-analysis, tool-based approach to detection-content QA rather than a live-monitoring or machine-learning approach. It is the most direct precedent for the proposed project's premise that detection rules are software artifacts whose quality can be assessed offline and at scale.

          This is the closest prior art to the proposed study: both treat detection rules as static artifacts subject to automated, deterministic, tool-driven quality scoring, both produce a weighted per-rule score, and both evaluate on a complete real-world corpus at a pinned commit. The critical difference is structural scope: sigmalint operates on Sigma rules largely as independent units and scores redundancy pairwise, whereas the proposed project targets Wazuh's parent-child (if_sid / if_matched_sid) DEPENDENCY GRAPH and performs multi-hop severity-bound propagation, a defect class (severity inversion originating several hops away) that a per-rule or pairwise scorer is structurally incapable of finding. The proposal must position itself as graph-aware severity-consistency analysis, not as another flat rule linter.

YOU CANNOT ESCAPE ME: DETECTING EVASIONS OF SIEM RULES IN ENTERPRISE NETWORKS
Uetz, Rafael; Herzog, Marco; Hackländer, Louis; Schwarz, Simon; Henze, Martin (2024)

33rd USENIX Security Symposium (USENIX Security 24), August 2024, Philadelphia, PA, USA, pp. 5179-5196, ISBN 978-1-939133-44-1; Distinguished Artifact Award winner; also arXiv:2311.10197. 

https://www.usenix.org/conference/usenixsecurity24/presentation/uetz

          This paper studies a quality defect in SIEM detection rules: many widely used rules can be trivially evaded, creating detection blind spots. The authors manually analyzed all process-creation Sigma rules present in the repository on 4 February 2021 (process-creation rules were 41% of all rules at the time of analysis) and found that of the 292 analyzed rules, 110 (38%) were fully evadable and 19 (7%) partially evadable using five straightforward evasion types, each demonstrated with a concrete example. To remedy this, they propose adaptive misuse detection, embodied in an open-source proof-of-concept system called AMIDES, which uses machine learning to compare incoming events both to SIEM rules and to known-benign events to discover successful evasions and to indicate which rule was evaded. Using four weeks of SIEM events from a large enterprise network plus more than 500 hand-crafted evasions, AMIDES detected a majority of evasions without false alerts and at a computational cost suitable for real-world operation. The work combines a manual defect study of an existing ruleset with a tool-based detection method evaluated using seeded (hand-crafted) evasion cases. 

          The similarities are strong at the level of research framing: both this study and the proposal begin from the premise that the default or widespread ruleset itself contains latent quality defects that silently degrade detection, and both quantify a defect class across a real corpus and use seeded/injected cases for evaluation (their 500+ hand-crafted evasions parallel the proposal's seeded-defect injection facility). The key difference is that this paper targets EVASION blind spots (rule matching logic that attackers can bypass) using a live, ML-based runtime system, whereas the proposal targets SEVERITY-COHERENCE defects using offline static graph analysis with no log ingestion, no ML, and no network access, addressing a defect that manifests even when a rule matches perfectly.

GLITCH: AUTOMATED POLYGLOT SECURITY SMELL DETECTION IN INFRASTRUCTURE AS CODE
Saavedra, Nuno; Ferreira, João F. (2022)

37th IEEE/ACM International Conference on Automated Software Engineering (ASE '22), October 10-14, 2022, Rochester, MI, USA; DOI 10.1145/3551349.3556945. 

https://doi.org/10.1145/3551349.3556945

          This study addresses the fragmentation of security-smell detection across Infrastructure-as-Code (IaC) technologies, where separate, inconsistent tools exist for each language. The authors present GLITCH, a tool that transforms scripts from multiple IaC technologies (Ansible, Chef, Docker, Puppet, Terraform) into a single intermediate representation and then applies rule-based analysis to detect security smells over that unified model. The intermediate representation captures shared concepts (projects, modules, unit blocks, attributes) so that one smell definition can be applied consistently across technologies, avoiding the inconsistent results that arise when each tool re-implements detection separately. GLITCH is implemented in Python and evaluated empirically for its smell-detection capability across the supported languages. The central contribution is that configuration artifacts written in a declarative language can be parsed, normalized into a graph/tree model, and statically checked for defect patterns. This is a canonical example of the software-engineering line of work the proposal draws its method from. 

          The methodological parallel is direct: both GLITCH and the proposal parse declarative configuration artifacts (IaC scripts there, Wazuh XML rules here), normalize them into an intermediate structural model, and run deterministic rule-based static checks to surface defects, then report findings. Both are explicitly offline static-analysis tools intended to be usable in developer/CI workflows. The difference the proposal addresses is the nature of the defect and the model: GLITCH detects local, mostly single-file security smells (for example, hard-coded secrets) via pattern matching, whereas the proposal analyzes a cross-artifact DIRECTED DEPENDENCY GRAPH and reasons about an ORDINAL property (severity level) that must remain consistent along multi-hop ancestor/descendant chains, requiring topological ordering and bound propagation rather than pattern matching.


CYBERSECURITY SKILLS IN NEW GRADUATES: A PHILIPPINE PERSPECTIVE
Miranda, John Paul P.; Tayag, Marlon I.; Canlas, Joel D. (2025)

December 2025, International Journal of Advances in Applied Sciences (IJAAS), vol. 14, no. 4, pp. 1217-1228, DOI: 10.11591/ijaas.v14.i4.pp1217-1228; also arXiv:2512.14778. Authors affiliated with Pampanga State University and Holy Angel University, Angeles City, Philippines.

https://doi.org/10.11591/ijaas.v14.i4.pp1217-1228

          This study addresses the gap between the skills cybersecurity graduates acquire and those employers require for entry-level roles, set against an acute local and global shortage of skilled cybersecurity professionals. Using a descriptive cross-sectional design, the authors combined a three-month analysis of job listings on Philippine online job platforms with surveys of students, teachers, and cybersecurity professionals on the importance of required competencies. They found broad agreement that communication, critical thinking, problem-solving, teamwork, adaptability, continuous learning, and ethics are highly necessary (median importance of 1 to 1.5 on their scale), signaling a shift away from a purely technical skillset, while business acumen was rated less vital at entry level. The authors recommend curricula emphasizing an inclusive blend of technical knowledge, soft skills, and ethical conduct. The study is a workforce analysis rather than a technical implementation.

          The connection to the proposed study is motivational and directly load-bearing: the proposal's central argument is that manual severity auditing across several thousand rules is never performed in practice, and this study evidences the Philippine expertise shortage that makes such manual auditing structurally impossible for local SOCs and MSSPs. Both works implicitly concern how scarce analyst attention should be allocated, which is exactly what severity level governs through alert routing and escalation thresholds. The difference is that Miranda et al. measure the human capital gap without proposing any tooling, whereas the proposed study supplies an automated static analyzer that removes the dependence on expert memory of the ruleset's dependency structure.

CYBERSECURITY PROGRAM FOR PHILIPPINE HIGHER EDUCATION INSTITUTIONS: A MULTIPLE-CASE STUDY
De Ramos, Noly M.; Esponilla, Francisco Dente II (2022)

September 2022, International Journal of Evaluation and Research in Education (IJERE), vol. 11, no. 3, pp. 1198-1209, DOI: 10.11591/ijere.v11i3.22863 (IAES, Scopus-indexed)

https://ijere.iaescore.com/index.php/IJERE/article/view/22863

          This study examines the cybersecurity readiness of Philippine State Universities and Colleges, whose management information systems face rising threats to student data and institutional assets. It uses a qualitative multiple-case design with structured interviews of purposively selected IT experts from SUCs in the National Capital Region, analyzed through thematic coding. The principal challenges identified were user education, cloud security, information security strategy, and unsecured personal devices. The authors propose a program logic model to guide cybersecurity planning, implementation, and assessment for national bodies including CHED, DICT, and PASUC. Both authors are affiliated with Philippine institutions. The findings characterize institutions that deploy monitoring capability without a corresponding quality-assurance function.

          The relevance to the proposed study is that Philippine academic institutions are named beneficiaries of open-source SIEM precisely because commercial licensing is unaffordable, and this study documents the strategy and expertise constraints under which such deployments are run. Both works are concerned with whether a deployed security capability actually delivers the protection it is assumed to provide. The gap the proposal addresses is that this study offers no examination of detection content quality at all; the proposed system converts an undocumented dependency held informally by experienced staff into an explicit, queryable, machine-checkable artifact, which matters most in exactly the understaffed institutions this study describes.
